# Project Environment

- Inspected: 2026-08-23 (Europe/Warsaw).
- Current state: Tauri 2 desktop application under construction. Rust 1.96 Cargo workspace implements the clipboard domain model, SQLite WAL/FTS5 store, serialized writer, content-addressed blob storage, thumbnails, Raycast/SuperCmd parsers, a resumable import service with a hard 256 MiB memory envelope, search/ranking, a read-only verification CLI, a typed Tauri command boundary, and a React/Vite palette with a virtualized history list.
- Rust workspace members: `clipboard-core`, `clipboard-store`, `clipboard-search`, `clipboard-images`, `clipboard-import`, `clipboard-zstd-bound`, `platform-macos`, `platform-linux`, `platform-windows`, `clipboard-history-app` (`src-tauri`), `clipboard-import-cli` and `clipboard-bench` (`tools/`).
- Frontend: `apps/desktop-ui` — React 19 + TypeScript 7 + Vite 8 + Vitest 4, `@tanstack/react-virtual`, local `@fontsource-variable` fonts (no CDN), `axe-core`. Talks to Rust through one gateway (`src/lib/gateway.ts`) mapping 13 `invoke` commands; `mockGateway.ts` renders the UI in a plain browser without Tauri.
- Schema: `PRAGMA user_version = 3` (migration number) plus `schema_identity(identity, revision)` with `revision = 6`. Migration 003 adds indexes only, which is why the identity revision did not move with it. Migrations in `crates/clipboard-store/src/migrations/`. Constraints are enforced in SQL `CHECK`s, not only in Rust.
- Current host/target: macOS on `aarch64-apple-darwin`. Windows and Linux adapters are implemented as policy/capability crates but have never been compiled for their targets; there is no checked-in CI.
- Native status: clipboard capture (`crates/platform-macos`), global shortcut (Cmd+Shift+Space), menu bar item, paste via Quartz Event Services, opt-in retention and blob reclamation are all implemented and running on macOS. Windows and Linux adapters exist as policy/capability crates with host-run tests but have never been compiled for their targets — only `aarch64-apple-darwin` is installed.
- Storage tiering follows the representation, not the entry kind: a textual representation of a file or image entry stays inline, only a binary one goes to the blob store. `classify_payload` and the verifier's shape audit must be changed together.
- File and image entries keep their source path as a `text/uri-list` representation; the importer never reads bytes from outside the export root.
- Plan status: all four plans are complete. Open by decision, not by oversight: `verify` is still unconditionally exhaustive (no `--full` split), `--expect-records` is still required rather than optional, and Windows/Linux remain unverified on their targets. Plans live in `docs/superpowers/plans/`, spec in `docs/superpowers/specs/`, per-task ledgers in `.superpowers/sdd/`.
- The implementation lives on `main`; the `feature/clipboard-manager` branch and its worktree were merged and removed on 2026-08-23.
- Build: `cargo build --workspace --locked`; `pnpm install` then `pnpm build` for the frontend.
- Quality gates: `cargo fmt --all --check`, `cargo check --workspace --all-targets --locked`, `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `pnpm test -- --run`, `pnpm typecheck`, `pnpm build`.
- Focused tests: `cargo test -p clipboard-import --test parsers --locked`, `cargo test -p clipboard-import --test service --locked`, `cargo test -p clipboard-search --test search --locked`, `cargo test -p clipboard-store --tests --locked`, `cargo test -p clipboard-import-cli --test cli --locked`, `cargo test -p clipboard-history-app --test commands`.
- CLI: `cargo run --locked -p clipboard-import-cli -- --help`; import mutates only an explicitly supplied safe data directory, verify opens an existing database read-only.
- Development database: `CLIPBOARD_HISTORY_DATA_DIR="data/dev" pnpm tauri dev`. `data/` is ignored and holds real private history; previous generations are preserved by directory rename, never deleted.
- Import facts worth not rediscovering: the supplied exports hold 6503 source records (5509 Raycast + 994 SuperCmd) that deduplicate to 5382 `content` rows, 485 of them without a payload (415 image, 70 file). The SuperCmd export contains no field linking an image record to an image file, so all 15 image entries stay without payload by design. Raycast image paths point into a cache it has already evicted (399 of 400 gone). Payloads outside the selected export root are never read.
- Argent: installed, but no simulator/mobile workflow applies here. The Chromium/Tauri surface becomes relevant once the desktop shell runs.
- Data caution: clipboard exports and ignored application data contain sensitive personal data. Never log, publish, commit, or copy their contents; tests use synthetic fixtures only.
- Scale is measured, not assumed. `tools/clipboard-bench` generates a synthetic history from a seed and measures it; the 2026-08-23 run at one million records is in README. Two defects only that run could find: neither `blob_relpath` column was indexed, so a bounded reclamation pass scanned the whole payload table per file; and the ranked-search usage join carried no row estimate, so the planner drove it from `history_event` and walked a million index entries before every search. Both are fixed.
- Ranked search costs time proportional to how many documents match, not to the result limit — relevance needs a score for every match. Selective queries are ~3 ms at a million records; a term matching 600k documents is ~811 ms. That is a documented limit, not a regression.
- `StoreHandle::with_reader` opens a fresh SQLite connection per top-level call and only reuses one when nested. On a large database that setup is a few milliseconds per call — wrap a loop of reads in one outer `with_reader`.
- The verifier reconciles against `importedEventCount`, not the total. Once the application captures the clipboard, a history event with no import record is an ordinary local capture; requiring one made a healthy database report `logicalStatus: failed`.
